02网络与安全组（重要）

当前外部访问状态：待放行 本机防火墙已确认放行（iptables INPUT ACCEPT、firewalld 关闭、SELinux 关闭），服务已监听 0.0.0.0。但 2026-10-18 从外部节点实测，只有 22 / 80 / 443 可连通，5434 / 6380 / 9010 / 9011 / 9876 / 10911 / 10909 全部超时。这是京东云安全组只放行了这三个端口导致的，需要在云控制台添加入站规则后，学员才能从外部直连。

需要放行的入站规则

协议端口用途建议来源
TCP5434PostgreSQL0.0.0.0/0 或学员出口 IP 段
TCP6380Redis同上
TCP9010MinIO S3 API同上
TCP9011MinIO Console同上（也可只放行 API）
TCP9876RocketMQ Nameserver同上
TCP10911RocketMQ Broker同上
TCP10909RocketMQ VIP 通道同上

控制台路径通常为：京东云控制台 → 云主机 → 安全组 → 入站规则 → 添加规则。若只允许学员访问，把来源改成学员的公网 CIDR 更安全。10912 是 HA 端口，单机主节点不需要放行。

临时替代：SSH 隧道

如果暂时不能改安全组，且有服务器 SSH 账号，可以把端口转发到本机（22 已开放）：

ssh -N \
  -L 5434:127.0.0.1:5434 \
  -L 6380:127.0.0.1:6380 \
  -L 9010:127.0.0.1:9010 \
  -L 9011:127.0.0.1:9011 \
  -L 9876:127.0.0.1:9876 \
  -L 10911:127.0.0.1:10911 \
  -L 10909:127.0.0.1:10909 \

然后在本地把下面所有地址中的 111.228.14.136 换成 127.0.0.1 即可。

04PostgreSQL 调用方式

连接串

jdbc:postgresql://111.228.14.136:5434/pipewise
postgresql://pipewise:{{PG_PASSWORD}}@111.228.14.136:5434/pipewise

命令行

psql -h 111.228.14.136 -p 5434 -U pipewise -d pipewise
# 密码：{{PG_PASSWORD}}

Python（SQLAlchemy / psycopg）

from sqlalchemy import create_engine, text
engine = create_engine(
    "postgresql+psycopg://pipewise:{{PG_PASSWORD}}@111.228.14.136:5434/pipewise")
with engine.connect() as conn:
    print(conn.execute(text("select version()")).scalar())

Node.js（pg）

import pg from "pg";
const pool = new pg.Pool({
  host: "111.228.14.136", port: 5434,
  user: "pipewise", password: "{{PG_PASSWORD}}",
  database: "pipewise"
});
console.log((await pool.query("select now()")).rows[0]);
  • pipewise 是数据库 owner，可以在库里创建自己的 schema/table；建议每个学员用 student_<name> 前缀。
  • 最大连接数 200，shared_buffers=256MB；不要在客户端建大量短连接，建议连接池 ≤10。
  • 当前未启用 TLS，密码与数据在公网明文传输，只放测试/教学数据。

07RocketMQ 调用方式

连接参数

项值
Nameserver111.228.14.136:9876
Broker111.228.14.136:10911（客户端由 nameserver 自动发现）
ACL Access Keypipewise
ACL Secret Key{{ROCKETMQ_SECRET_KEY}}
Topic / Group自动创建；建议 student_<name>_topic、student_<name>_group
ACL 已验证 无凭据发送会被拒绝；带上述 access/secret 的 Java 生产者发送成功（测试消息 ID AC18000700080533DDBA59AF49D60000）。Python 客户端 v2.0.0 使用 set_session_credentials(access_key, secret_key, "LOCAL")。

Java 生产者

DefaultMQProducer producer = new DefaultMQProducer(
    "student_demo_producer",
    new AclClientRPCHook(new SessionCredentials(
        "pipewise", "{{ROCKETMQ_SECRET_KEY}}")));
producer.setNamesrvAddr("111.228.14.136:9876");
producer.start();
SendResult r = producer.send(new Message(
    "student_demo_topic", "hello rocketmq".getBytes(StandardCharsets.UTF_8)));
System.out.println(r.getSendStatus() + " " + r.getMsgId());
producer.shutdown();

Maven 依赖：org.apache.rocketmq:rocketmq-client:5.3.1 与 org.apache.rocketmq:rocketmq-acl:5.3.1。

Java 消费者

DefaultMQPushConsumer consumer = new DefaultMQPushConsumer(
    "student_demo_consumer",
    new AclClientRPCHook(new SessionCredentials(
        "pipewise", "{{ROCKETMQ_SECRET_KEY}}")));
consumer.setNamesrvAddr("111.228.14.136:9876");
consumer.subscribe("student_demo_topic", "*");
consumer.registerMessageListener((MessageListenerConcurrently) (msgs, ctx) -> {
    for (MessageExt m : msgs) {
        System.out.println(new String(m.getBody(), StandardCharsets.UTF_8));
    }
    return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
});
consumer.start();

Python 生产者

from rocketmq.client import Producer, Message

p = Producer("student_demo_producer")
p.set_name_server_address("111.228.14.136:9876")
p.set_session_credentials("pipewise", "{{ROCKETMQ_SECRET_KEY}}", "LOCAL")
p.start()

msg = Message("student_demo_topic")
msg.set_keys("demo")
msg.set_body("hello rocketmq")
print(p.send_sync(msg))

p.shutdown()

Python 消费者

from rocketmq.client import PushConsumer, ConsumeStatus

def callback(msg):
    print(msg.body.decode())
    return ConsumeStatus.CONSUME_SUCCESS

c = PushConsumer("student_demo_consumer")
c.set_name_server_address("111.228.14.136:9876")
c.set_session_credentials("pipewise", "{{ROCKETMQ_SECRET_KEY}}", "LOCAL")
c.subscribe("student_demo_topic", "*")
c.register_message_callback(callback)
c.start()
# 保持进程运行；退出时 c.shutdown()
  • Broker 对外宣告的地址是 111.228.14.136:10911，客户端必须能访问该地址；9876 与 10911/10909 都要放行。
  • 自动创建 Topic/Group 已开启；仍建议显式使用独立名字，避免误消费别人的消息。
  • 单机主节点、异步刷盘，适合教学；不要用于生产关键数据。

09运维手册

常用命令

cd /opt/pipewise-infra

docker compose ps                 # 状态
docker compose logs -f postgres   # 日志（redis/minio/rocketmq-* 同理）
docker compose restart redis      # 重启单个服务
docker compose stop               # 停止全部（数据保留）
docker compose up -d              # 启动全部
docker compose down               # 删除容器（不删 named volume）
docker compose down -v            # 连数据一起删除（危险）

备份与恢复

# PostgreSQL 逻辑备份
docker exec pipewise-postgres pg_dump -U pipewise -d pipewise > /opt/pipewise-infra/backup-$(date +%F).sql
# 恢复
cat backup.sql | docker exec -i pipewise-postgres psql -U pipewise -d pipewise

# Redis：触发 RDB 快照（AOF 已在写）
docker exec pipewise-redis redis-cli -a {{REDIS_PASSWORD}} BGSAVE

# MinIO：镜像到本地目录
mc mirror pipewise/student /opt/pipewise-infra/backup-minio/student

# RocketMQ：停 broker 后打包 store 卷（或直接备份底层磁盘）
docker compose stop rocketmq-broker
docker run --rm -v pipewise-infra_brokerstore:/data -v /opt/pipewise-infra:/backup alpine \
  tar czf /backup/rocketmq-store-$(date +%F).tgz -C /data .
docker compose start rocketmq-broker

查看数据卷位置

docker volume inspect pipewise-infra_pgdata --format '{{.Mountpoint}}'
docker volume ls | grep pipewise

重启后检查

docker compose ps
docker logs --tail 20 pipewise-rocketmq-broker | grep 'boot success'
curl -s http://127.0.0.1:9010/minio/health/live && echo minio-ok

10故障排查

现象原因处理
外部连接全部超时，服务器本机正常云安全组未放行端口按第 02 节添加规则；本机 iptables 已确认放行
服务器上用公网 IP 连自己超时NAT 不支持 hairpin（回环）服务器本机请用 127.0.0.1；外部学员用公网 IP
RocketMQ broker 反复重启named volume 属于 root，容器用户 uid 3000 无法写入部署脚本已自动 chown 3000；手动修复见下
Docker Hub 拉镜像超时网络抖动重跑部署脚本（已存在镜像会跳过）；或配置镜像加速
Redis NOAUTH没带密码使用 -a 或连接串里的密码
MinIO SignatureDoesNotMatchAccess/Secret 错误或签名版本不对确认密钥；boto3 指定 s3v4
RocketMQ 发送超时但端口通ACL 未配置或 access/secret 错误客户端同时配置 AclClientRPCHook（或 Python 的 set_session_credentials）

手动修复 RocketMQ 卷权限：

docker run --rm --user root \
  -v pipewise-infra_brokerstore:/store \
  -v pipewise-infra_brokerlogs:/logs \
  -v pipewise-infra_namesrvlogs:/nlogs \
  apache/rocketmq:5.3.1 \
  sh -c 'chown -R 3000:3000 /store /logs /nlogs'
docker compose restart rocketmq-namesrv rocketmq-broker

11安全与使用约定

仅教学数据

PG/Redis/RocketMQ/MinIO 都是明文协议（无 TLS），密码和数据在公网可被嗅探。不要放真实个人信息、密钥或生产数据。

限制来源 IP

安全组尽量只放行学员出口 IP 段，而不是 0.0.0.0/0；课程结束及时收回规则。

不要共用 root 权限

MinIO root 账号、PG owner 权限都很大。学员练习建议用 student 桶、独立 schema/key 前缀。

定期轮换

课程结束后修改四个密码：编辑 /opt/pipewise-infra/.env 后重跑部署脚本；MinIO/Redis/PG 会按新密码重建容器。
