01背景与目标

流程引擎解决了「事情按规则流转」，但没有解决「人要在节点上读懂材料、查制度、做判断」。AI 能力如果只是外挂一个聊天窗口，就无法进入流程上下文，也无法被评测和治理。本 PRD 要把 AI 做成流程的一部分。

1.1 三类现状问题

知识在文档里，不在流程里

合同条款、报销制度、HR 政策散落在网盘和知识库，审批人靠搜索和记忆，新人上手慢，口径不一致。

AI 能力是孤岛

业务方各自接模型、写提示词、做 RAG，重复建设；没有版本、没有引用、没有评测，效果好坏说不清。

Agent 无法进入流程

Agent 的输出无法写回流程上下文，不能参与分支、审批、超时和审计；流程也无法约束 Agent 的权限与成本。

1.2 产品目标

目标描述验收信号
G1 知识可用的流程知识库接入流程节点，回答必须带引用；无命中时明确说「不知道」审批节点可展示引用来源；引用可点开原文
G2 人人可搭 Agent业务人员用表单化配置完成 Agent：提示词、知识、工具、输出结构、护栏非研发在 30 分钟内搭出一个可测试的 Agent
G3 Agent 可嵌入流程Agent / 知识检索 / 分类 / 抽取作为流程节点，输入输出映射到上下文流程设计器可拖入 AI 节点并发布
G4 可评测可回归数据集、评测器、发布门禁、版本对比；Agent 变更先评测再上线发布 Agent 必须通过评测阈值或显式豁免
G5 可治理成本、延迟、权限、审计、安全护栏、模型路由可按实例追溯每次 Agent 调用的输入、引用、工具、成本

1.3 非目标（本期不做）

  • 不做通用聊天机器人 / 通用 AI 助手产品；所有 AI 能力服务流程节点与流程上下文。
  • 不做模型训练、微调、蒸馏平台；只做模型接入、路由与调用治理。
  • 不做 RPA、浏览器自动化、任意代码执行。
  • 不做「AI 自动审批高风险事项」；高风险节点必须保留人工确认。
  • 不做通用低代码页面搭建或 BI 报表。

02产品定位与边界

一句话定位 AI 能力层是流程引擎之上的「知识与智能编排层」：知识库提供可信事实，Agent 提供可复用的智能单元，评测提供上线前的质量证明，流程负责把三者放进正确的业务上下文。

2.1 三层能力 + 一层编排

图 2-1 AI 能力不另起一套业务系统，而是嵌入既有流程引擎的分层。

2.2 做与不做

做不做
流程节点上的知识检索、抽取、分类、建议、摘要脱离流程的通用 AI 聊天产品
业务人员可配置、可测试、可发布的 Agent任意代码执行、RPA、浏览器自动化
Agent 版本与流程版本绑定，运行期可追溯Agent 修改后静默影响运行中实例
上线前离线评测、上线后采样评测与人工反馈只靠感觉判断「效果好」
引用、置信度、人工确认、失败回退无依据自动决策、无人工兜底

2.3 设计原则

  • 流程优先：AI 节点必须能读写流程上下文、参与分支与审批，而不是弹窗。
  • 引用可核验：知识回答必须带来源；无引用时降级为「不确定」。
  • 版本钉住：流程实例钉住 Agent 版本与知识库版本，发布不改变在跑实例。
  • 评测先行：Agent 发布、流程发布涉及 AI 节点时，默认要求评测门禁。
  • 人机协同：高风险场景 Agent 只给建议，人工做最终决定。
  • 成本可预算：每个 Agent / 节点 / 租户都有 token 与金额预算。

03用户角色与核心场景

3.1 角色

角色关心什么典型动作
知识管理员知识是否全、准、新；谁能看建知识库、上传/同步文档、配置权限、处理解析失败、看命中率
Agent 搭建者（业务/流程 BP）Agent 能不能解决业务问题、输出稳不稳定配置提示词、绑定知识、测试、发布版本、看评测报告
流程设计者Agent 如何嵌入流程、失败怎么办拖入 AI 节点、配置输入输出映射、阈值、超时与回退边
审批人 / 业务用户AI 建议是否可信、依据在哪查看摘要与引用、采纳/修改/驳回建议、反馈好坏
评测 / 标注人员数据集是否有代表性、评分是否一致建评测集、标注、跑评测、看失败聚类
平台管理员模型、工具、配额、成本、安全接入模型、配置路由、设配额、看大盘、处理告警
安全 / 合规数据不出域、PII 不泄露、操作可审计审权限、审模型与工具、查调用留痕

3.2 核心场景

S1 合同审批：Agent 做预审，人做决定

发起上传合同 PDF
→
AI 抽取金额/主体/期限/违约条款
→
知识检索合同制度 + 历史条款
→
风险 Agent给出风险点与引用
→
人工审批采纳/修改/驳回
→
结束记录采纳率

流程节点返回结构化风险等级与引用；高风险自动加签法务。Agent 不直接决定通过。

S2 报销预审：规则 + 知识 + 抽取

OCR/抽取 Agent 读取发票与明细，规则节点校验金额和标准，知识 Agent 解释不合规原因；低置信度转人工。审批人看到「为什么不合规」和制度原文。

S3 HR 政策问答：表单里的知识助手

员工在请假/报销表单中提问，知识 Agent 基于制度库回答并给出引用；回答只做解释，不修改表单字段，除非用户确认。

S4 工单分流：分类 Agent + 排他网关

分类 Agent 输出 category / priority / confidence，排他网关按类别路由到不同处理流程；置信度低于阈值时走人工分诊。

S5 Agent 评测：发布前的质量证明

Agent 搭建者用 100 条历史工单作为评测集，运行准确性、引用忠实度、工具调用正确率三项评测；未达阈值不能发布，除非管理员填原因豁免。

05知识库

5.1 定位

知识库是「流程可引用的可信事实源」。它不是网盘，也不是通用问答库：每个知识库有明确负责人、可见范围、更新方式与质量指标；Agent 引用时必须返回来源片段。

5.2 知识库配置

配置项说明默认
名称 / 描述 / 分类面向业务人员的可读信息必填名称
负责人 / 管理员对内容质量与权限负责创建者
可见范围租户 / 部门 / 角色 / 指定用户租户内
切分策略按标题 / 段落 / 固定 token / 自定义分隔符按标题+段落，500 token，重叠 50
检索配置向量 / 关键词 / 混合；TopK；重排开关混合检索，TopK=6，重排开
无命中策略返回空 / 返回「不确定」/ 触发人工返回不确定，不编造
敏感级别普通 / 内部 / 机密；影响模型与导出内部

5.3 文档接入

方式说明优先级
本地上传PDF / DOCX / MD / HTML / TXT；批量上传；大小上限MVP
URL 抓取定时抓取网页正文，去导航与广告MVP
开放 API业务系统推送文档与元数据MVP
连接器飞书文档、Confluence、共享网盘、数据库表P1

文档状态机

UPLOADED → PARSING → CHUNKING → INDEXING → READY
                ↘ FAILED（可重试 / 查看原因）
READY → STALE（源文档更新）→ REINDEXING → READY
READY → DISABLED（负责人手动下线）

解析失败必须给出可操作原因（加密 PDF、扫描件无 OCR、格式不支持、文件过大），并支持单篇重试与批量重试。

5.4 解析、切分与元数据

  • 解析：文本、标题层级、表格、图片说明；扫描 PDF 走 OCR（P1），无 OCR 时明确标记「仅图片」。
  • 切分：按语义边界优先；表格不跨块；每块保留文档标题、章节路径、页码/URL、更新时间。
  • 元数据：部门、制度编号、生效日期、失效日期、适用人群；检索可按元数据过滤。
  • 去重：同文档多版本只保留最新有效版本；重复上传提示覆盖或并存。

5.5 检索与引用

Query用户问题 + 上下文
→
混合召回向量 + 关键词
→
重排相关性 + 时效 + 权限
→
组装TopK 片段 + 引用
→
回答带来源，无命中说不确定
  • 每条引用包含：文档名、片段、页码/URL、更新时间、知识库、片段 ID；前端可点开原文定位。
  • 检索必须遵守调用者权限：用户看不到的文档不能被 Agent「代为检索」出来。
  • 无命中或相关性低于阈值时，Agent 输出「未找到依据」，不得编造。
  • 知识库提供「检索测试」：输入问题，查看召回片段、分数、引用，不调用大模型。

5.6 权限与版本

层级权限
知识库查看 / 编辑 / 管理 / 删除；负责人可转移
文档继承知识库；可对单篇设置更严格可见范围
Agent 调用以 Agent 的服务身份检索，但仍受「调用者数据范围」约束
版本文档版本可追溯；重新索引生成新索引版本，旧版本保留一段时间

5.7 质量指标

  • 文档解析成功率、索引成功率、平均索引延迟。
  • 检索命中率、引用点击率、无命中率、人工反馈「没找到/找到了」。
  • 陈旧文档占比（超过 N 天未更新）、失效文档占比。

5.8 边界

  • 加密/扫描 PDF：明确提示需要 OCR 或人工上传可复制版本。
  • 超大文档：拆分为多文档或分段上传，单文档有大小上限。
  • 表格与图片：MVP 只保留表格文本；图片 OCR/多模态 P1。
  • 删除知识库：被 Agent 引用时禁止直接删除，需先解绑或迁移。

06Agent 搭建

Agent 是可复用的智能单元：有明确的输入契约、输出契约、知识范围、工具权限与版本。业务人员用表单配置，研发只在必要时写工具或脚本。

6.1 Agent 定义

配置说明必填
名称 / 描述 / 图标 / 分类业务可读标识；支持模板复制名称
Agent 类型对话 / 任务 / 抽取 / 分类；决定默认输出形态是
模型模型或模型路由策略；温度、最大输出 token是
系统提示词角色、边界、拒答策略、输出要求是
用户提示词模板引用流程变量，如 {{contract_text}}是
知识库选择一个或多个；TopK、过滤条件、是否必须引用否
工具HTTP/OpenAPI、MCP、只读流程查询、计算器；逐个授权否
输出 SchemaJSON Schema；字段类型、必填、枚举任务/抽取/分类必填
护栏PII 脱敏、提示词注入防护、内容安全、禁止自动决策默认开
超时 / 重试 / 预算单次超时、重试次数、token/金额上限默认值

6.2 提示词与变量

  • 系统提示词与用户模板分离；模板支持流程上下文变量、知识片段占位、工具结果占位。
  • 变量必须声明来源与类型；缺失时按配置「报错 / 空值 / 走兜底」。
  • 提示词修改必须生成新版本；发布前跑评测。

6.3 知识绑定

  • 可选多个知识库；按优先级召回；可配置元数据过滤（部门、生效日期）。
  • 默认要求引用；无引用时 Agent 必须输出低置信度或走人工。
  • 知识库版本随 Agent 版本钉住；知识更新后需重新发布 Agent 版本才能生效（或显式允许跟随最新）。

6.4 工具调用

工具类型示例约束
HTTP / OpenAPI查客户、查发票、查库存域名白名单、超时、幂等键、只读优先
MCP内部数据服务、搜索服务工具级授权、参数校验、调用审计
流程只读查询查当前实例、查历史审批只读、按实例数据范围
计算器金额、税额、日期差确定性计算，不让模型心算

工具返回必须结构化；工具失败时 Agent 可选择重试一次、降级回答或返回失败，不允许编造工具结果。

6.5 输出契约

{
  "answer": "string",
  "confidence": 0.0,
  "citations": [{"docId":"...","chunkId":"...","title":"...","page":3}],
  "structured": { "riskLevel": "high", "clauses": [...] },
  "needHuman": true,
  "reason": "string"
}

流程节点只依赖 structured 与 confidence、citations、needHuman；自然语言答案用于展示，不参与路由判断。

6.6 测试台

  • 输入变量，运行 Agent，查看输出、引用、工具调用、耗时、token 与成本。
  • 保存测试用例；支持从测试用例一键加入评测集。
  • 版本对比：同一输入在两个版本下的输出、引用、成本和延迟并排展示。

6.7 版本与发布

DRAFT → TESTING → PENDING_REVIEW → PUBLISHED → DEPRECATED
                    ↘ REJECTED
  • 发布后不可变；任何修改生成新版本。
  • 发布门禁：评测通过率、引用忠实度、工具正确率、成本上限；未通过需管理员豁免并记录原因。
  • 流程版本引用 Agent 版本；已发布流程不会被 Agent 新版本静默影响。

6.8 模板与复制

  • 内置模板：合同风险审阅、发票抽取、工单分类、政策问答、摘要助手。
  • 复制 Agent 生成新草稿，保留配置但不继承发布状态。
  • 模板库按部门/场景分类；P2 支持内部分发与收藏。

07Agent 与流程集成

这是本 PRD 的核心增量：Agent 不是外挂，而是流程里的节点。节点有输入映射、输出映射、超时、回退边和预算；运行期可追溯，版本可钉住。

7.1 AI 节点类型

节点KEY行为典型场景优先级
知识检索ai_knowledge检索知识库，返回片段与引用；不调用或可选调用模型总结制度查询、条款定位MVP
Agent 节点ai_agent调用已发布 Agent，按输出 Schema 写回上下文合同风险、报销预审、摘要MVP
分类节点ai_classify输出枚举 + 置信度，配合排他网关路由工单分流、意图识别MVP
抽取节点ai_extract从文档/文本抽取结构化字段发票、合同、简历MVP
AI 辅助审批ai_review生成建议与引用，人工审批任务同时展示审批 CopilotP1
安全护栏ai_guard敏感信息、注入、内容安全检查；失败走异常边对外文本、附件P1

7.2 节点配置

配置说明
Agent / 知识库 / 模型版本必须选择已发布版本；流程发布时钉住
输入映射从流程上下文、表单字段、附件、上一步输出映射到 Agent 变量
输出映射把 Agent 结构化输出写入流程变量；字段缺失按默认值/报错
超时 / 重试默认 30s，超时 1 次重试；长任务用异步节点（P1）
置信度阈值低于阈值走人工回退边
回退边模型失败、无引用、低置信度、预算超限时走指定出边
预算单次 token/金额上限；超限停止并走回退
引用要求必须引用 / 可选引用 / 不要求；必须引用但无引用时视为失败

7.3 执行语义

  • 同步：默认；节点调用 Agent，等待结果后推进令牌。超时按回退策略。
  • 异步（P1）：长任务生成 Agent Run，节点 WAITING；完成后回调唤醒，支持取消。
  • 幂等：调用键为 instanceId + nodeInstanceId + attempt；重复投递不重复计费。
  • 上下文：Agent 只读上下文快照，输出以补丁方式写回；不允许 Agent 直接修改流程状态。
  • 审计：每次调用记录 Agent 版本、知识库版本、引用、工具、模型、token、成本、耗时。

7.4 人机协同模式

模式行为适用
建议 + 人工决定AI 生成建议和引用，审批任务展示；人工采纳/修改/驳回合同、报销、高风险审批（默认）
自动处理 + 抽样复核高置信度自动完成低风险节点，按比例抽样人工复核低风险分类、信息补全（需显式开启）
低置信度转人工置信度低于阈值或引用不足，走人工边所有 AI 节点默认策略
人工先审后 AI 执行人确认后 Agent 执行生成/汇总对外文本、客户沟通

7.5 版本钉住与迁移

  • 流程版本发布时记录 Agent 版本与知识库版本；运行中实例只读这些版本。
  • Agent 新版本发布不影响在跑实例；需要时走显式迁移工具（P2）。
  • 知识库允许「跟随最新」模式，但必须在节点配置中显式选择，并在时间线标记。

7.6 失败与回退

失败行为
模型超时 / 限流重试一次；仍失败走回退边，默认转人工
输出不符合 Schema重试一次；仍失败记录原始输出，走回退边
无知识命中按配置：返回不确定 / 走人工 / 终止；不得编造
引用缺失但要求引用视为失败，走回退边并告警
工具失败记录错误；可降级回答或走回退边；不得伪造工具结果
成本超预算停止调用，节点失败，实例按配置挂起或走回退边
权限不足拒绝检索/工具调用，明确提示，不降级为猜测

08Agent 评测

评测不是发布后的报表，而是发布前的门禁。没有评测集的 Agent 不允许直接进入生产流程。

数据集人工 / 线上采样 / 文档生成
→
运行固定版本 + 并发执行
→
评分规则 + LLM Judge + 人工
→
报告通过率 / 失败聚类 / 对比
→
门禁通过才可发布

8.1 评测对象

对象评什么
Agent 版本任务完成质量、结构化输出、工具调用、引用
知识库检索召回率、引用正确率、无命中识别
流程 + Agent 组合端到端是否推进正确、是否走对回退边

8.2 数据集

  • 人工构建：业务专家按场景编写输入与期望输出，支持 CSV/JSON 导入。
  • 线上采样：从真实实例抽样，脱敏后加入数据集；需权限审批。
  • 文档生成：从知识库生成 QA 对，人工审核后入集。
  • 数据集版本化，支持训练/验证/测试切分与标签（场景、难度、风险等级）。

8.3 评测器

评测器说明适用
精确匹配 / 包含答案或字段与期望完全一致 / 包含关键词分类、枚举、抽取
JSON Schema 校验输出结构、类型、必填、枚举所有结构化 Agent
关键字段准确率指定字段逐项比对发票、合同抽取
引用忠实度回答是否被引用片段支持知识问答、风险审阅
答案相关性是否回答了用户问题问答类 Agent
工具调用正确率工具选择、参数、次数是否正确带工具的 Agent
LLM-as-Judge按评分 rubric 由强模型打分，需人工抽检校准开放式回答
人工评分标注员按标准打分与写理由金牌集、争议样本
安全评测注入、越权、PII 泄露、有害内容所有对外 Agent

8.4 评测运行与报告

  • 选择 Agent 版本 + 数据集 + 评测器 + 采样策略，创建评测运行。
  • 报告包含总体通过率、分场景通过率、失败样本、失败聚类、耗时与成本。
  • 支持两个版本对比：质量变化、成本变化、延迟变化。
  • 失败样本可一键加入下一轮数据集或标注队列。

8.5 发布门禁

门禁默认阈值未通过
总体通过率≥ 85%阻断发布，可管理员豁免并填原因
高风险场景通过率≥ 95%阻断发布，不允许豁免
引用忠实度≥ 90%阻断发布
安全评测0 高危阻断发布
单次平均成本≤ 预算警告，需说明

8.6 线上评测

  • 按比例采样线上调用，异步跑轻量评测器；不阻塞流程。
  • 收集用户反馈：采纳 / 修改 / 驳回、点赞点踩、引用点击。
  • A/B：同一流程按比例分流到 Agent vN 与 vN+1，比较采纳率与人工override率。
  • 指标异常（引用下降、override 上升）自动告警，可一键回滚到上一版本。

8.7 标注与人审

  • 标注队列按场景/难度分配；提供评分标准与示例。
  • 双人标注抽检，计算一致性；争议样本进入专家仲裁。
  • 标注结果反哺评测集与提示词优化，形成闭环。

09模型、工具与运行时

9.1 模型网关

  • 统一接入多家模型（公有云/私有化/本地）；模型注册包含上下文长度、价格、能力标签。
  • 路由策略：按任务、成本、延迟、可用性选择；支持主备降级。
  • 凭证与密钥集中管理；按租户/Agent 配额；调用日志脱敏。
  • 模型下线/变更提前告警；Agent 版本钉住模型或路由策略。

9.2 工具注册

  • HTTP/OpenAPI 导入；MCP Server 接入；只读流程查询作为内置工具。
  • 工具级权限、超时、重试、幂等键、响应大小限制。
  • 工具调用审计：谁、何时、哪个 Agent、参数摘要、结果摘要、耗时。

9.3 运行时

  • 同步调用 + 异步队列；超时、重试、熔断、限流。
  • 上下文组装：系统提示 + 用户输入 + 检索片段 + 记忆 + 工具结果，按 token 预算裁剪。
  • 流式输出（P1）：首 token 时间、断线重连；流程节点默认等完整结果。
  • 语义缓存（P2）：相同问题/上下文复用结果，需标注缓存命中。

9.4 安全与权限

  • 知识检索按调用者数据范围过滤；Agent 服务身份不能越权。
  • 提示词注入防护：文档内容视为数据，不执行其中指令；高风险工具需人工确认。
  • PII 识别与脱敏：输入、日志、评测集；可配置保留策略。
  • 数据不出域：按租户/知识库选择模型区域与供应商。

10可观测、成本与治理

10.1 调用追踪

一条 trace 串起：流程实例 → 节点实例 → Agent Run → 检索 → 工具 → 模型调用。每一步记录输入摘要、输出摘要、耗时、token、成本、错误。

指标说明告警
调用成功率成功 / 总调用< 99%
P95 延迟按 Agent/节点超过 SLA
Token / 成本按 Agent、流程、租户超预算 80% / 100%
引用覆盖率有引用的回答占比< 阈值
人工 override 率修改/驳回 AI 建议的比例上升 10%
评测通过率线上采样评测低于门禁

10.2 成本预算

  • 预算层级：租户 → 流程 → Agent → 节点；每层可设日/月上限。
  • 超 80% 告警，超 100% 停止调用并按节点回退策略处理。
  • 成本看板按模型、Agent、流程拆分，支持导出。

10.3 审计

  • 知识库文档增删改、Agent 配置/版本/发布、评测运行、模型与工具变更全部留痕。
  • 每次 AI 调用可回答「用了哪个版本、哪些知识、哪个模型、花了多少钱」。
  • 审计日志 append-only，权限与保留期可配置。
